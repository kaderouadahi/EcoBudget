# H9 Compte e-mail facultatif — Plan d'implémentation

> **Pour l'exécutant :** superpowers:executing-plans (inline, choisi par Kader). superpowers:test-driven-development pour les règles (conditions du mot de passe, messages selon les erreurs Firebase, avertissement « N dépenses », Réglages › Compte dans ses deux états, déconnexion refusée hors connexion). superpowers:verification-before-completion avant de dire « fait ». Cases `- [ ]` pour le suivi. **Budget : 2 h.** Ce qui marche passe avant ce qui est parfait.

**Objectif :** créer un compte (le compte anonyme devient un compte e-mail), se connecter sur un autre appareil, se déconnecter, avec Réglages › Compte dans ses deux états. Plus aucun texte souligné dans toute l'application.

**Architecture :** les règles pures vont dans `src/lib/account.ts` (conditions, adresse, message selon le code d'erreur Firebase, avertissement). Les appels Firebase, minces, vont dans `src/auth/actions.ts`. `AuthGate` expose `useAccount()` (uid, e-mail, anonyme ou non, `refresh`), remonte l'application quand l'uid change et repasse en chargement à la déconnexion. `BrowserRouter` et `ToastProvider` passent au-dessus d'`AuthGate` : les messages et la navigation survivent au changement de compte. Écrans dans `src/features/account/` (`BareLayout`, déjà routé). Section Compte dans `src/features/settings/AccountSection.tsx`.

**Stack :** React 19, react-router 7, Firebase Auth 13 (`linkWithCredential`, `EmailAuthProvider`, `signInWithEmailAndPassword`, `sendPasswordResetEmail`, `signOut`), Firestore (`waitForPendingWrites`), Vitest + Testing Library, puppeteer-core (E2E, `$CLAUDE_JOB_DIR/tmp/shot/`).

**Spec :** `docs/HANDOFF.md` § H9. `docs/DECISIONS.md` : 17/11 (données et comptes, connexion sur un autre appareil), 20/11 (H7 Compte, remplacée), 21/11 (×6). Maquettes `telephone-08/10/11`, `ordinateur-08/09/10`.

## Contraintes globales (textes exacts de la spec)
- Messages d'erreur, de confirmation et de l'avertissement :
  - Conditions : « Au moins 8 caractères », « Au moins un chiffre ». Rond gris vide, puis vert avec coche dès qu'elle est remplie. Texte caché « Condition remplie » / « Condition non remplie ». Après un essai raté : la ligne non remplie passe en rouge avec icône.
  - Adresse : « Adresse incomplète : ajoutez la fin, par exemple yasmine@gmail.com ». Création : « Un compte existe déjà avec cette adresse. » avec le lien « Se connecter ».
  - Mot de passe : « Le mot de passe doit contenir au moins 8 caractères, dont un chiffre. »
  - Hors connexion : « Connectez-vous à internet pour créer votre compte. » ; « Connectez-vous à internet pour vous connecter. » ; « Connectez-vous à internet pour vous déconnecter : vos dernières dépenses doivent d'abord être enregistrées dans votre compte. »
  - Connexion : « Adresse e-mail ou mot de passe incorrect. » (sous le mot de passe) ; « Trop d'essais. Réessayez dans quelques minutes, ou utilisez « Mot de passe oublié ? ». »
  - Mot de passe oublié : « Saisissez votre adresse e-mail pour recevoir le lien. » ; « Si un compte existe pour cette adresse, un e-mail vient d'être envoyé pour choisir un nouveau mot de passe. »
  - Avertissement : « Cet appareil contient **N dépenses** notées sans compte. Elles **ne seront pas ajoutées** à votre compte et ne seront plus visibles ici. » Au singulier : « Cet appareil contient **1 dépense** notée sans compte. Elle **ne sera pas ajoutée** à votre compte et ne sera plus visible ici. » Encadré bleu avec icône, jamais orange. Affiché seulement s'il y a au moins une dépense.
  - Messages après action : « Compte créé : vos données sont enregistrées dans votre compte. » ; « Vous êtes connecté » ; « Vous êtes déconnecté ».
- Créer un compte (`/compte/creer`) : « Créer un compte », « Facultatif ». Bandeau nuage : « Retrouvez vos dépenses sur tous vos appareils. **Ce que vous avez déjà noté est conservé.** » Champs :
  - « Prénom (facultatif) », prérempli, aide « Affiché sur l'accueil », règles `cleanFirstName` (H7) ;
  - « Adresse e-mail » ;
  - « Mot de passe », avec « Afficher » / « Masquer ».
  - Bouton « Créer mon compte », lien « J'ai déjà un compte. Se connecter ».
- Se connecter (`/compte/connexion`) : « Se connecter », « Retrouvez vos données ». Champs sans liste de conditions, lien « Mot de passe oublié ? », bouton « Se connecter », lien « Pas encore de compte ? Créer un compte ».
- Réglages › Compte :
  - sans compte : nuage, « Sans compte pour l'instant », « Vos données sont enregistrées de façon anonyme. Créez un compte pour les retrouver sur un autre appareil. », « Créer un compte » (bleu, icône personne) et « Se connecter » (contour), côte à côte ;
  - connecté : nuage avec coche, « Connecté », adresse, « Vos données sont enregistrées dans votre compte : vous les retrouvez sur tous vos appareils. », « Se déconnecter » (contour).
  - Prénom inchangé dessous.
- Déconnexion : « Se déconnecter ? » ; « Vos données restent dans votre compte : vous les retrouverez en vous reconnectant. Cet appareil repartira sans données. » ; « Rester connecté » / « Se déconnecter » (bleu, pas rouge). Ensuite : nouveau compte anonyme vide et Première ouverture. Hors connexion : pas de fenêtre.
- `auth.languageCode = 'fr'`. Règles Firestore inchangées. `/demo` inchangé.
- Aucun texte souligné dans toute l'application : liens et boutons texte en bleu vif et en gras ; contour de focus au clavier conservé.

## Points à surveiller (non couverts par les tests de la spec)
1. **Connexion à un autre compte** : rien de l'ancien compte ne doit s'afficher ni rester abonné. Test T2 (enfants remontés quand l'uid change).
2. **Déconnexion avec un réseau capricieux** (`navigator.onLine` vrai, serveur injoignable) : `waitForPendingWrites` ne répond pas. Au bout de 10 s, on refuse avec le message hors connexion, sans `signOut`. Test T2.
3. **Double appui** sur « Créer mon compte » ou « Se connecter » : un seul appel à Firebase. Tests T4 et T5.
4. **Adresse saisie avec des espaces** («  Yasmine@gmail.com  ») : espaces retirés avant l'envoi. Test T2.
5. **Après la création du compte**, Réglages affiche « Connecté » sans recharger. Le lien ne déclenche pas `onAuthStateChanged`, d'où `refresh()`. Tests T2 et T4.

**Correspondance des codes d'erreur :**

| Action | Code Firebase | Champ | Message |
|---|---|---|---|
| create | `email-already-in-use`, `credential-already-in-use` | email | « Un compte existe déjà… » (`kind: 'exists'`) |
| create | `invalid-email` | email | Adresse incomplète |
| create | `weak-password` | password | Règle du mot de passe |
| create | `network-request-failed` | form | Hors connexion (création) |
| create | autre | form | « Le compte n'a pas pu être créé. » (`kind: 'retry'`) |
| signin | `invalid-credential`, `invalid-login-credentials`, `wrong-password`, `user-not-found` | password | Adresse ou mot de passe incorrect |
| signin | `too-many-requests` | password | Trop d'essais |
| signin | `invalid-email` | email | Adresse incomplète |
| signin | `network-request-failed` | form | Hors connexion (connexion) |
| signin | autre | form | « La connexion n'a pas abouti. » (`kind: 'retry'`) |
| reset | `invalid-email`, `missing-email` | email | « Saisissez votre adresse… » |
| reset | `network-request-failed` | form | « Connectez-vous à internet pour recevoir le lien. » |
| reset | `too-many-requests` | form | « Trop d'essais. Réessayez dans quelques minutes. » |
| reset | autre | form | « L'e-mail n'a pas pu être envoyé. » (`kind: 'retry'`) |

Les textes « autre » et « reset réseau » ne sont pas fixés par la spec : ce sont des choix, à noter dans les écarts.
