# H1 Dépenses — Plan d'implémentation

> **Pour l'exécutant :** superpowers:executing-plans ; TDD pour `lib/expenses.ts` et `lib/budget.ts` ; superpowers:verification-before-completion avant « fait ».

**Objectif :** noter, modifier, supprimer (avec confirmation et « Annuler ») une dépense en quelques gestes, dès la première ouverture ; Accueil avec bienvenue et dernières dépenses ; état du budget dans le message quand il atteint 80 %.

**Architecture :** logique pure testée dans `src/lib/` ; un `DataProvider` unique abonné aux collections de l'utilisateur (catégories, dépenses, budgets, réglages) via `repo.ts` (H0) ; formulaire `ExpenseForm` sans accès aux données (props), branché par les pages `NewExpense` / `EditExpense`.

**Spec :** `docs/HANDOFF.md` § H1 ; DECISIONS.md prime ; maquettes `telephone-01`, `02`, `03`.

## Contraintes globales
- Montant : entier > 0 en DA ; aide « En dinars, sans centimes. Exemple : 250 ».
- Catégories par défaut, ids fixes (création idempotente) : `repas` Repas (UtensilsCrossed), `courses` Courses (ShoppingCart), `transport` Transport (BusFront), `sorties` Sorties (Ticket), `sante` Santé (Heart), `logement` Logement (House), `etudes` Études (BookOpen), `autres` Autres (Ellipsis, `locked: true`).
- Catégorie proposée = celle de la dernière dépense (par `createdAt`), Repas pour la toute première ; libellé « Proposée : Repas ».
- Date du jour par défaut ; date future refusée : « La date ne peut pas être dans le futur ».
- Après enregistrement : retour Accueil, message « Dépense ajoutée : 250 DA, Repas » (+ « · Courses : il reste 6 000 DA » ou « · Courses : dépassé de 900 DA », ton warn/danger avec icône, quand le budget de la catégorie est à ≥ 80 % après la dépense).
- Suppression : confirmation « Supprimer cette dépense de 2 500 DA ? » puis « Dépense supprimée » avec « Annuler ».
- Dernières dépenses : 4 plus récentes ; titre = note sinon catégorie ; sous-titre « Catégorie · jour » ; montant `formatDA(-amount)`.

## Review Focus
1. Montant saisi avec espaces (« 2 500 ») → accepté = 2500 ; « 2,5 » / « 2.5 » → refusé (décimal).
2. Catégorie de la dernière dépense supprimée entre-temps → proposer Repas (ou la première catégorie).
3. Double clic sur « Enregistrer la dépense » → une seule dépense (bouton désactivé après le premier envoi).
4. Annuler une suppression recrée la dépense avec le même id et les mêmes champs.
5. Budget à 0 dépense puis dépense qui le fait passer de 79 % à 80 % pile → état affiché (80 % inclus).

### Tâche 1 : Logique des dépenses et de l'état de budget (TDD)
**Fichiers :** `src/lib/expenses.ts` (+ test), `src/lib/budget.ts` (+ test), `src/data/defaults.ts`.
**Produit :**
- `parseAmount(text: string): { ok: true; value: number } | { ok: false; error: string }` — vide → « Saisissez un montant en dinars, par exemple 250 » ; décimal → « Sans centimes : saisissez un nombre entier, par exemple 250 » ; ≤ 0 → « Le montant doit être supérieur à 0, par exemple 250 » ; espaces retirés.
- `validateDate(iso: string, today: Date): string | null` — futur → « La date ne peut pas être dans le futur » ; vide → « Choisissez une date ».
- `proposedCategoryId(expenses: Expense[], categories: Category[]): string`.
- `latestExpenses(expenses: Expense[], n = 4): Expense[]` (date desc, puis createdAt desc).
- `expenseTitle(e: Expense, c?: Category): string`.
- `budgetState(spent: number, budget: number): { kind: 'ok'|'warn'|'over'; remaining: number }` — calcul entier (`spent*100 >= budget*80`) ; 79 % ok, 80 % warn, 100 % warn, 101 % over.
- `budgetNotice(categoryName, spent, budget): { text: string; tone: 'warn'|'danger' } | null` — null sous 80 % ; « Courses : il reste 6 000 DA » ; « Courses : dépassé de 900 DA ».
- `DEFAULT_CATEGORIES` (ci-dessus) et `CATEGORY_ICONS: Record<string, LucideIcon>`.
**Tests :** chaque message exact ci-dessus ; « 2 500 » → 2500 ; « 2,5 » refusé ; proposition = dernière par createdAt, Repas si aucune, Repas si catégorie disparue ; ordre des dernières dépenses ; 79/80/100/101 %.
